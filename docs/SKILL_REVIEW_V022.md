# 剧本 Skill 二次审订

本次只调整 Skill 与文档。目标是让它作出更有依据的编辑判断，并准确说明验证范围。

## 主要修订

- 删除“一段最多一个比喻”的硬性配额。直接表达感情、重复、技术词和修辞都可以有效，判断依据是人物、节奏和场景作用。
- 增加事实边界。把抽象句改成落灰、危险、回忆或肢体动作，都可能新增设定；具体不等于正确，优先使用已经成立的细节。
- 人物声线先看动机、知情范围和关系，再看句式。普通应答可以相似，商人也不必永远只注意钱和货物。
- 选择回调必须来自实际经历；润色不应顺手新增奖励、好感或态度变化。
- 区分状态测试与触发测试。手动解锁流浪者只能验证解锁后的菜单，不能证明计时器正常。
- 区分保存页导航与存读档往返。后者需要保存、改变状态、读取并核对恢复结果。
- 隐形按钮标签不能单独证明无障碍和热点正确；烘焙文字仍需考虑缩放及本地化成本。
- 文档与检查按改动范围选择，避免每改一句话都填写完整场景表、打包所有平台。

## 对照案例推演

这些是规则层面的人工推演，未执行独立模型实验，不能作为 Skill 提升幅度的量化证据。

| 输入情境 | 修订后应作出的判断 |
| --- | --- |
| “出口比答案更要紧”不自然，但原场景没有坍塌迹象 | 可以改成收好路线图、走向出口；不能自行补出建筑即将倒塌的事实 |
| 技术出身主角正在检修设备，使用“协议” | 根据知识背景和现场用途判断，不能按词表删除 |
| 两个人都说“知道了” | 允许普通应答相似；不为区分声线强加口癖 |
| 文本设置解锁标志后隐藏路线测试通过 | 只报告解锁后菜单和路线通过，计时回调另行验证 |
| 点击保存入口能打开页面 | 只证明页面导航，不宣称已完成存档恢复验证 |
| 用户只要求润色一段夜谈 | 保留无关 UI、构建与部署，只核对受影响文本和分支 |

## 既有复盘的证据更正

上一轮确有 lint、compile、剧情分支测试与 APK 安装成功记录。但现有摘要中的暂停测试显示打开保存页并返回，没有足够证据证明实际存读档往返；隐藏入口测试直接设置了解锁状态，也没有证明两分钟触发链正常。应缩窄相关结论，而非把测试方法当作完整功能验收。

本次没有重新运行游戏功能测试，也没有改写其测试代码。Skill 结构校验只验证可加载性；上述行为判断仍需在后续真实编辑中观察效果。
