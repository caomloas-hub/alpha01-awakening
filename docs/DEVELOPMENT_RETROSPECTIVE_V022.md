# v0.2.2 开发实战复盘

本轮把《风从旧世来》从“能够运行的序章与城镇线原型”推进到具有统一标题、菜单、场景文字、声音反馈和 Android 测试包的版本。复盘重点不是罗列产物，而是保留那些会改变后续开发判断的经验。

## 本轮范围

- 游戏正式名称统一为《风从旧世来》；“ALPHA-01”仅保留为剧情实验编号，“苏醒记录”保留为档案功能名。
- 重做标题、主菜单五枚按钮、暂停菜单和法庭固定标牌。
- 连续重读序章与城镇第一章，清除硬套口癖、格言式收尾和抽象名词堆叠。
- 将商路音乐、环境声、事件声与界面反馈拆分，并替换刺耳的通用提示音。
- 保持剧情标签、菜单文字、变量、持久化字段和分支汇合点不变。
- 完成 Windows 语法、编译、关键分支与菜单流程测试，并汇编、安装 Android v0.2.2 测试包。

## 有效的设计判断

### 1. 静态文字属于美术，动态信息属于程序

标题、固定按钮文字和法庭中的实体标牌不会随玩家状态变化，直接融入图片能让材质、透视、磨损、阴影和装饰形成一个整体。玩家姓名、存档日期、页码、编号等会变化的内容仍应由 Ren'Py 绘制。

这个边界比“一律烘焙文字”或“一律后期叠字”更可靠：前者会破坏可变内容和可访问性，后者容易产生悬浮文字与画面材质不融合的问题。

### 2. 点击反馈必须作用于整个按钮

旧实现只让文字滑动，边框和装饰仍停在原地，玩家会感到按钮被拆成了两层。本轮改为整张带字按钮参与悬停、按下和退场动画，Ren'Py 只保留透明热点、键盘焦点和行为逻辑。

透明热点仍然保留不可见文本标签，使自动测试、键盘操作和界面语义不依赖图像识别。移动端不能依赖 hover 才能表达可点击状态，按下反馈和足够大的触控区域必须独立成立。

### 3. 标题资产要参与世界观，而不是盖在背景上的字体

《风从旧世来》被做成带透明通道的独立标题资产：旧世金属、残存蓝光、藤蔓、城镇剪影和抓住“旧”字的龙共同承担世界观信息。标题放在右上角，避开左侧阶梯菜单，并保持龙只是次要剪影，不压过字形识别。

### 4. 第一人称限制反而提升了连续性

主角不露完整身体后，生成图不再需要反复猜测全身服装、尾孔和比例。画面只展示确有叙事必要的爪、袖口、地图或视线边缘；真正换衣时再使用对应的第一人称 CG。这既减少了生成错误，也让玩家视角更加稳定。

### 5. 一张优秀 CG 也不能兼任多个地点

城门图质量很高，但让它同时承担国道、南市、栈院和通铺房会破坏空间感。本轮明确了重新上路、通过验籍门、进入南市、抵达南栈院和进入通铺房等切换点。资产是否漂亮不能代替场景是否正确。

### 6. 文学性来自选择细节，而不是漂亮话密度

最有效的改写不是替换几个词，而是改变情绪的承载方式：商人注意货签和数量，守门人注意证词漏洞，谨慎的主角注意出口和手的位置。动作已经表达情绪时，不再追加抽象总结；紧张场面缩短句子，转场和观察允许适当拉远。

角色性格也不能依靠重复口癖。理性角色通过观察顺序和风险判断表现理性，幽默角色不必句句抖机灵，次要人物不应共享主角的语言精度。

### 7. 声音先建立空间，再服务情绪

声音被拆成环境、事件、界面和音乐四层。验籍门的人群声只播放足以建立空间的几秒；断轴、地图展开和兽爪点图具有各自的可听原因；菜单悬停与确认采用短而轻的机械木质声，不再复用剧情提示音。

最终响度和情绪适配仍交给实际聆听验收，波形或文件检查只能证明资源存在，不能证明声音好听。

## 暴露的问题与修正

### 生成与构图

- 三视图曾出现尾巴方向错误，说明生成前必须明确视角和身体连接关系。
- 换衣 CG 的袖口与剧情状态冲突，后来改为第一人称、只展示已经穿好的局部。
- 临时准入证明最初像现代公文，信息过于直白；改成斜置木牌，只通过黄色提示说明获得了“灰桥城临时准入证明”。
- 地图兽爪看似位置接近，实际指尖热点仍偏移。透明素材应先裁掉无效边缘，再以指尖而非图片中心作为锚点，逐个记录落点。
- 法庭“被告人”文字后期悬浮在画面上，最终改为与标牌透视和材质一起生成。

### 剧本与分支

- “出口比答案更重要”“让时代承认我存在”等句子脱离当下动作，读起来像作者总结。改写后由灰尘、木牌、铜币、货单和第二天的工作承担情绪。
- 三条出身路线不应一开始并列。流浪者路线继续由等待触发，路线概念图则随选择前的对话逐张出现，而不是脱离叙事自动播放。
- 本轮隐藏入口测试直接设置“等待已完成”状态，验证了解锁后的选项与路线；这不验证实际计时回调。后续触发测试应使用生产回调与可控时间，或实际等待。
- 一句分支文本曾少缩进一级。Ren'Py lint 没有把它视为语法错误，但它会改变菜单结构。关键菜单必须结合实际分支测试和人工阅读检查，不能只依赖 lint。

### 工程与平台

- Windows 下直接运行 `renpy.exe` 可能不把输出正确连接到当前终端。使用独立隐藏进程并重定向标准输出、错误输出更稳定。
- Ren'Py 8.5.3 的 Android 构建会在正式编译前强制校验 JDK 21；Android 工具包自带的 JDK 17 无法通过。便携 JDK 21 配合 RAPT、API 36 后成功构建。
- Android 构建完成不等于实机体验通过。包名、版本号和横屏声明可以自动核对，但画面裁切、软键盘、触控手感和声音仍需要用户实机验收。
- 多个自动剧情测试连续运行时，前一条路线的持久状态可能污染下一条。关键路线既要能单独运行，也要明确重置共享状态。

## 固化后的工作循环

1. 先冻结不可变契约：标签、菜单文字、变量、持久化字段、分支汇合点和已有存档目录。
2. 为每个场景写清当前地点、时间、服装、可见角色、叙事目标、CG、环境声和关键动作声。
3. 判断文字属于世界实体、固定 UI 还是动态数据，再决定烘焙进图片或由引擎绘制。
4. 每张资产完成“生成—接入—加载测试—用户验收”后再进入下一张，避免批量生成后一起返工。
5. 文本先解决会改变画面的事实，再生成资产；接入后进行连续阅读和最终润色。
6. 运行 lint、compile 和受影响的关键分支测试；涉及菜单时检查测试是否真的进入目标分支。
7. Android 只在 Windows 版本稳定后打包。先核对 JDK、RAPT、API、包名、版本号和方向，再决定是否进行实机安装。
8. 审美、节奏和听感由用户验收；自动检查只负责证明文件能加载、流程能抵达和状态能正确写入。

## 本轮验证结果

- Ren'Py 8.5.3 lint：通过。
- Ren'Py compile：通过。
- 法庭两种回应、流浪者隐藏入口、城门三种回答与城镇第一章：通过针对性测试。
- 暂停、进入保存页与返回导航：通过。实际保存后读取并恢复状态的往返测试尚无充分记录。
- Android：使用 JDK 21、RAPT 和 API 36 成功生成 v0.2.2 APK。
- 实机：ADB 覆盖安装成功，设备报告应用版本 `0.2.2`；视觉体验仍由用户验收。

## 下一轮建议

- 开发流浪者路线前，先建立路线自己的地图、服装、声音空间和特殊人物表，不强行复用商队资产。
- 保留“场景—资产—声音—变量”清单，但不引入 SHA 或完整文件树审查。
- 每完成一段可玩的路线，就把新暴露的通用经验收敛进 Skill；只记录会改变下一次决策的规则，避免把单次修改意见全部堆成永久流程。

有关规则边界和验证结论的后续审订，见 [Skill 二次审订](SKILL_REVIEW_V022.md)。
