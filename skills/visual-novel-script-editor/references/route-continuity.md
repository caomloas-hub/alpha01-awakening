# 多场景与分支连续性

用于整章复查、可选事件回调、路线汇合及新路线规划。只记录有复用风险的状态，不要求逐句建表。

## 分清四层信息

1. 世界中实际发生的事（也包括尚未揭晓的作者设定）。
2. 玩家已经看到的内容，包括非主角视点、旁白及其他通关路线。
3. 当前周目主角亲历、听闻、推测的内容。
4. 当前说话 NPC 亲见、被告知或推测的内容。

每条有争议的回调追问一次来源：谁、何时、在哪条分支知道？若找不到，不能用“他聪明所以猜到了”补洞。推断可以成立，但须有可见线索，并保留推断语气。

全局 persistent 的解锁记录不等于本周目的经历。不要用上次通关的记录决定当前背包或人物知情。一个字段若先表示地表行动、后表示出身路线，也不能据其最终值倒推早先行动。

## 三类常见汇合错误

- 有人没做修车任务，汇合台词却夸他安装过新撑：条件化回调，或使用所有路径确实发生的救援。
- 离线核心是可选取得，夜间却人人都有：检查取得和持有状态；若不需提及，删除无条件清点，而非强给玩家道具。
- 主角心里盘算过钱，NPC 却引用了这句盘算：私下念头不是交流记录。

修订应选择最小方案。新增变量有旧存档迁移成本；删除一次无关的清点通常不需要搭建背包系统。若道具影响后续剧情，则须正式设计独立持有状态，不能靠删句掩盖机制缺失。

## 物理与经济连续性

核对衣物“试穿—标记—脱下修改—重新穿好”，不要让平放桌上的衣料同时贴着身体。核对伤势、随身物品、路线方向、经过时间、日落关门条件。金额需对应交付时点：约定总额、已付、扣除、余额不能各说各的。

没有道具来源时，优先找已存在的取得事件。确需补充动作，明确这是连续性修补带来的小新增；若它改变危险、能力、关系或新资产需求，先提出方案。

## 规划与验证

将作者批准的路线骨架和待定设计分开。新路线可继承序章状态，但不能继承另一条互斥路线的衣服、知识或人情。共享地理不代表共享地图制作者与标注重点。

整章完成后，至少比较一条缺少可选经历的路径和一条包含相关经历的路径。人工审读证明台词语义是否自洽；引擎测试证明条件、数值和流程能运行。两者不能互相代替，不宣称遍历未执行的所有组合。

长篇工程化与知识分层参考 zenstory-ai/oh-story-claudecode（MIT），但不引入其全套状态文件、事务、发布或多代理流程。
