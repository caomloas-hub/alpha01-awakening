# 作者反馈与声线校准

用于作者纠正风格、提供范文或要求更新长期写作规则时。普通改句不需要改 Skill。

## 不把一次修改变成永久口癖

保留：原文、作者实际修改/明确认可的版本、所在场景、适用范围。助手提出但作者未确认的文本只标“候选”；作者认可音乐、CG 或总体方案，不能据此宣布同轮全部台词已验收。

区分项目审美与故事事实。“不要连续升华”是表达偏好；“少女在林间救下主角”是情节；“少女因为愧疚救他”可能只是助手推测。三者不要混存。

从反馈提炼一个可验证判断，例如“谈价时先把条件说明白”，而不是“这个角色永远短句”“全文不能出现意义”。以后有相反场景，以作者最新指示和具体情境调整。

## 人物模型要允许变化

写角色在此刻想得到什么、担心付出什么、面对谁；必要时记录相互冲突的需求。例如想帮忙却怕承担责任，可以表现为明确担保边界，不必每句都讲道理。

不要把新推断的内在矛盾直接写成既定身世。角色在权威面前的谨慎、熟人面前的松弛是可考察维度，不是必须强加的反差。作者提供样本时，观察决策与关系如何影响语气，不只提取常用字词。

## 留下少而有用的例子

优先收录真实编辑中能区分“该改”和“该留”的例子。若某条新规则导致事实漂移、全员同声或语气过度口语化，缩小或撤回它；不要再堆一条补丁。结构校验成功只代表 Skill 能被读取，不代表文学效果改善，也不是独立模型评测。

角色结构的启发来自 alchaincyf/nuwa-skill（MIT）。反馈对照是独立编写的方法；jzOcb/writing-style-skill 在审阅时未发现许可证，因此不复制其正文、脚本或模板，也不自动执行其学习流程。
